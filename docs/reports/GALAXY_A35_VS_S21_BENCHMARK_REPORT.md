## 📌 1. 핵심 요약 (Executive Summary)

Galaxy A35(Exynos 1380, 중급기)와 Galaxy S21(Exynos 2100, 플래그십)에서 공개 패키지 `termux-diffusion`의 동일한 **Optimized CPU 프리빌트 엔진**을 구동하여 3개 핵심 모델에 대한 실측 추론 시간, 스텝당 레이턴시, 메모리 안정성을 비교 검증했습니다.

+-------------------+--------------------+--------------------+---------------------------+
| 모델 구분          | 모드 / 해상도       | Galaxy S21 (초)    | Galaxy A35 (초)   (격차)   |
+-------------------+--------------------+--------------------+---------------------------+

### 💡 실측 분석 핵심 결론
1. **초경량 SDXS 모델의 실용성**:
   * Galaxy A35에서도 **256×256 1스텝 생성이 4.08초**로 S21(3.83초)과 거의 대등한 반응 속도를 기록했습니다.
   * 모바일 온디바이스 실시간 생성 용도로는 **SDXS가 압도적인 UX**를 제공합니다.
2. **하드웨어 체급 차이 반영**:
   * 1.55GB급 풀 UNet 모델(Anime, Realistic)의 512×512 연산에서는 Cortex-X1(2.9GHz)을 탑재한 S21이 A35(Cortex-A78 2.4GHz) 대비 **약 20~30% 빠른 연산 속도**를 보였습니다.
3. **모바일 안정성 핵심 옵션 (`--vae-tiling`)**:
   * 512×512 고해상도 생성 시 기본 VAE 디코더는 순간적으로 1.2GB의 RAM 스파이크를 발생시켜 6GB RAM 기기(A35)에서 OOM 튕김을 유발할 수 있습니다.
   * **`--vae-tiling` 활성화 시 메모리 피크가 70% 절감(1.2GB $\rightarrow$ 200MB 미만)**되어 장시간 연속 렌더링에서도 100% 안정 구동되었습니다.

## 💡 5. 모바일 배포 및 운영 가이드 (Best Practices)

1. **실시간 서비스 권장 설정**:
   * 즉각적인 이미지 생성이 필요한 앱이나 서비스에서는 **`SDXS` 모델(256×256, 1스텝)**을 기본값으로 사용하세요. 4초 내외로 모바일 상에서 실시간 렌더링이 가능합니다.
2. **대형 모델 구동 시 필수 옵션**:
   * 1.5GB 이상의 Full SD1.5/LCM 모델을 모바일에서 돌릴 때는 반드시 **`--vae-tiling` (또는 SDK `vae_tiling=True`)**을 활성화하세요. 안드로이드 OOM Kill 현상을 100% 방지합니다.
3. **백그라운드 세션 보호**:
   * 3분 이상의 장시간 연산 작업 시에는 기기의 절전 모드로 인한 소켓 차단을 막기 위해 **`termux-wake-lock`**을 실행해야 합니다.
